# Качество

Политика возраста едина: seo_system/config/freshness.json. Для pages максимум 14 дней по дате исходного сбора; новая загрузка не омолаживает источник. Будущее время и неправильный порядок дат отвергаются. site_revision профиля и источника должны совпадать. После релиза нужна новая проверка затронутых URL, даже если старый crawl ещё моложе 14 дней.

Критические проверки: верный project/host, checksum, типы и количество строк, отсутствие дубликатов URL, chronology/freshness/revision, разрешимые evidence, отсутствие противоречий, ссылки задач на findings, report + priority + roadmap + coverage. Нельзя компенсировать провал критической проверки средней оценкой качества текста.

MVP применяет только три правила: HTTP >= 400, пустой title и пустой h1 на HTTP 200. Они дают наблюдения и задачи ревью. HTTP 404 может быть намеренным; автоматического требования восстановить любой URL нет. Индексация, canonical, CWV и orphan pages по этим полям не выводятся. Нулевое число находок не означает здоровый сайт.

Выход всегда partial, включая go: нет полного SEO-аудита. Missing fields отражаются в coverage; не генерировать по ним находки. Для расширения правил добавлять проверенные входные поля, acceptance tests и ограничения выводов.

Секреты и клиентские данные не должны попадать в Git. scripts/check_repository.py проверяет подготовленный индекс и рабочее дерево управляемых Git-файлов на характерные секреты/запрещённые пути; это вспомогательный барьер, не полная DLP-проверка. Сырые выгрузки и персональные данные должны оставаться вне репозитория.
