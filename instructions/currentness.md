# Актуальность и решения адаптации

Проверено 06.11.2026 по первичным публичным источникам. Это методическая проверка, не авторизация пользовательских аккаунтов. Если источник изменился или рекомендация влияет на решение проекта, перечитать первичную страницу. Vendor — исторический материал; действуют эти исправления и предметные процедуры.

| ID | Что исправлено | Основание |
|---|---|---|
| C01 | Удалено обещание FAQ rich results и обязательная FAQ-разметка для каждой страницы. FAQ-контент сохраняется, если полезен. Google сообщает о прекращении показа этого feature с 07.05.2026; прежняя FAQ-документация перенаправляется в updates. | [Google changelog](https://developers.google.com/search/updates) |
| C02 | Убраны универсальные keyword density, минимум 200 ключей, 300 слов, фиксированное число ссылок и обязательный размер pillar/spokes. Объём зависит от задачи и фактов, не служит сам по себе SEO-приёмкой. | [People-first content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content) |
| C03 | Ограничения title 60 и description 155 не являются жёсткими правилами поисковика. Проверять ясность, уникальность и реальное отображение; редакционные ориентиры подписывать. | [Title links](https://developers.google.com/search/docs/appearance/title-link), [Snippets](https://developers.google.com/search/docs/appearance/snippet) |
| C04 | AI-видимость измеряется отдельно от рекомендаций; не обещать цитирование и не утверждать знание закрытого алгоритма. Для AI-функций Google не требуются особые дополнительные SEO-оптимизации. Не объявлять llms.txt требованием Google. | [AI features](https://developers.google.com/search/docs/appearance/ai-features), [Google updates](https://developers.google.com/search/updates) |
| C05 | Разделять измерения CWV и гипотезы причин. Нужны LCP/INP/CLS с методом; HTML-анализ и TBT не подтверждают field INP. Origin и URL, lab и field не смешиваются. | [Core Web Vitals](https://developers.google.com/search/docs/appearance/core-web-vitals) |
| C06 | Автоматические disavow по «toxicity score» исключены. Инструмент нужен лишь в отдельных обоснованных обстоятельствах; сам provider score не доказывает санкцию. | [Disavow guidance](https://support.google.com/webmasters/answer/2648487) |
| C07 | Покупка ссылок, массовые doorway/scaled страницы и вымышленные отзывы/эксперты не следуют из SEO-поручения. Link/PR роли готовят полезные активы и drafts, внешние действия требуют реального scope полномочий. | [Spam policies](https://developers.google.com/search/docs/essentials/spam-policies) |
| C08 | Для Product проверять конкретный feature и действующую спецификацию; не переносить старый единый список required fields на все варианты product snippets/merchant listings. Не генерировать несуществующие отзывы. | [Product structured data](https://developers.google.com/search/docs/appearance/structured-data/product) |
| C09 | Sitemap — источник URL и сигнал обнаружения, а не доказательство индексации. Indexability и actual index status проверяются отдельно для нужного поисковика. | [Яндекс: Sitemap](https://yandex.ru/support/webmaster/ru/controlling-robot/sitemap) |
| C10 | GSC требует конкретную property и разрешение. API возвращает top rows и не гарантирует полноту; отсутствие строки не доказывает отсутствие в поиске. Средняя position — агрегат, не отдельный SERP rank. | [Search Analytics API](https://developers.google.com/webmaster-tools/v1/searchanalytics/query) |
| C11 | Яндекс: фиксировать dimensions/metrics и их совместимость, sampling/ограниченность данных. Общее OAuth-подключение не подтверждает доступ к конкретному counter/host. Версию API Вебмастера сверять с актуальным контрактом. | [Метрика](https://yandex.ru/dev/metrika/ru/stat/), [Вебмастер](https://yandex.ru/dev/webmaster/doc/ru/) |
| C12 | Labrika используется шире технического аудита: ключи/посадочные, позиции, конкуренты, контент, ссылки и AI. Для каждого отчёта нужны свои реальные поля, coverage и способ доступа; публичная документация не доказывает доступ аккаунта или универсальный API. | [Документация](https://labrika.ru/help), [Таблица ключей](https://labrika.ru/help/docs/keywords-table), [Ссылки](https://labrika.ru/help/docs/foreign-links) |
| C13 | Отдельно хранить наблюдения AI с исходным ответом, prompt/platform/time/mention/citation и рекомендации GEO. Не превращать маркетинговые заявления сервиса в факты о клиентском рынке. | [Видимость AI](https://labrika.ru/help/ai/vidimost-ai), [AI audit](https://labrika.ru/help/ai/vidimost-brendov) |
| C14 | Мониторинг изменений и генерация товарных описаний — отдельные функции с отдельными правами и расходом. Они не означают API всех SEO-отчётов и не запускаются при обычном чтении готового анализа. | [Monitoring](https://labrika.ru/website-change-monitoring), [Product descriptions](https://labrika.ru/product-descriptions) |
| C15 | Оценка «стоимости агентства» исключена из фактического ROI. Реальный результат требует затрат, ценности и attribution; CPC-equivalent, LTV-прогнозы и экономия времени — отдельные модели с допущениями. | Решение адаптации по контрактам данных и измерений |
| C16 | Исправлены несуществующие aliases competitor-spy/gap-analyst в исходной team-инструкции. Активные ссылки строятся по реальным IDs из roles.json; vault/output не образуют две редактируемые копии результата. | Сверка pinned upstream и каталогов |

Не поддерживаемые фактами рекомендации становятся гипотезами или missing inputs. Никакой суммарный quality score не компенсирует ложные данные. Не превращать актуальную методичку в обещание конкретного ранжирования.
