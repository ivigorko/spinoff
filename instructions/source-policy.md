# Политика источников

Свежие данные одного анализа использовать повторно в пределах совместимого scope. Не запускать новый crawl, если пригодная выгрузка уже доступна. Наличие цифр из Метрики в Labrika не создаёт второй независимый первичный источник; сохранять primary_origin и метод.

Источник для отдельных выводов выбирается по фактическому доступу, полям, дате, охвату и правам. Не приравнивать отчёт об ошибках к полной таблице URL. Конфликтующие наблюдения разных источников сохранять отдельно с объяснением периода/фильтров, а не усреднять молча.

Отдельно учитывать documented, account_verified, executor_verified, export_verified и api_verified для каждого отчёта. Успешный OAuth не подтверждает все properties, отчёты и API. Diff API Labrika и API описаний товаров не означают универсальный API технических/позиционных отчётов.

Исследование рынка и поисковых правил требует актуальных первичных источников. Матрица docs/source-matrix.md описывает категории из исходного задания; этот запуск не подтверждал доступ к пользовательским аккаунтам или актуальную полноту продукта.
