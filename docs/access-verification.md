## Реальный формат и исправление

Native Sheet с существующим регламентом SEO-работ экспортирован в XLSX: 19923 байта, один лист, worksheet dimensions отсутствуют (`max_row/max_column = None`). Локальный импортёр прежде сравнивал None с лимитом и мог завершиться TypeError. Исправлено: размеры проверяются, когда заданы, и дополнительно ограничиваются фактически прочитанные строки/столбцы. Структурный synthetic fixture повторяет отсутствие dimensions без копирования клиентского содержимого.

Добавлена команда `seo inspect-import`: только просмотр контейнера, hash, листов и опционально первой строки. Она не делает сетевых запросов, не считает inspected-файл свежим или авторизованным и не запускает анализ.

Реальный файл является регламентом, а не измерениями страниц: его нормализация в pages корректно отклонена из-за неподходящих заголовков. Не синтезировались URL/HTTP-коды, не менялись исходные даты и не создавался ложный клиентский аудит. Упоминания Labrika в документах — вторичный контекст, не исходный экспорт и не проверка аккаунта.

27 тестов проходят, включая dimensionless XLSX parser/E2E/лимиты и запрет интерпретировать таблицу задач как pages. Полный сценарий import→findings→report→priority→roadmap остаётся проверенным на синтетических данных; реальный измерительный dataset пока не получен.

## Данные и следующий шаг

Исходный XLSX и приватное свидетельство с file ID, временем, hash и результатами проверок находятся в игнорируемом workspace/read-probes-20261106/. В Git нет реальных клиентских выгрузок, OAuth-значений, личных данных пользователя или private source IDs. Ничего не отправлялось в сторонние AI/поисковые провайдеры, не менялись ACL, папки и документы, не запускались анализы и генерация, расходующие лимиты SEO-сервисов.

Ближайший шаг — выбрать пилот и конкретный существующий технический отчёт/его ID либо разрешённый счётчик/property. При наличии готового файла Drive можно прочитать его уже проверенным инструментом; новые доступы для этого не нужны. Проверить source date/scope/колонки и сохранить raw с checksum, затем запустить реальный import. Для проверки Метрики достаточно известного разрешённого counter ID и малого read-only запроса через найденный tool; для GSC понадобится действующее подключение, но в этом проходе оно не запрашивалось. Drive write/read smoke test и storage adapter остаются отдельным следующим этапом.
