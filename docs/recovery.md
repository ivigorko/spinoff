# Восстановление локального запуска

SQLite используется одним локальным исполнителем. `BEGIN IMMEDIATE` блокирует второго писателя; при занятой БД команда завершается с ошибкой, без неограниченных retry. Multi-worker не поддерживается. SQLite должна находиться на устойчивом локальном диске вне синхронизации Drive.

До commit создаётся частный .staging-UUID. При обычной ошибке удаляется только собственный staging. После аварийного завершения он может остаться; не считать его принятым результатом. Проверь отсутствие работающего процесса, исходный manifest и содержимое перед ручным перемещением в recovery-каталог. Не удалять единственную копию клиентских результатов.

Узкое окно: rename каталога выполнен, но commit SQLite не завершён. Следующий запуск обнаружит unregistered run directory и остановится. Сохрани каталог вне projects/.../runs под именем с UUID в том же приватном workspace, затем повтори команду с исходными неизменёнными входами. Не исправляй реестр вручную по одному имени папки. Внешних записей и платных вызовов в MVP нет, повтор безопасен после сохранения незарегистрированной копии.

При отсутствующем или изменённом зарегистрированном файле reuse блокируется. Восстанови точные байты из проверенной копии; при её отсутствии используй новый приватный workspace для повторного расчёта. Не подменяй checksum в SQLite ради прохождения проверки.

Для резервного копирования останови исполнителя и скопируй весь workspace, включая SQLite и projects. Drive backup/reconciliation и автоматическое восстановление из manifest пока не реализованы. Потеря локального диска означает потерю единственной копии, если пользователь её не сохранил отдельно.

Процессная библиотека хранит отдельные process-state.sqlite3 и projects/<project>/processes/<run>/. Profile/plan заморожены в state; frozen.json — экспорт, state является источником истины. Sources/products immutable и проверяются по hash. Client evidence сохраняет также original bytes с отдельным hash. Изменение/новая версия источника получает новый source ID, принятого продукта — новый run.

Файловая система и SQLite не образуют общую транзакцию. После аварии между созданием файла и commit возможен orphan source/product/frozen export; он не считается принятым и не перезаписывается благодаря exclusive create. Сначала сохранить единственную копию и сверить registry; для повторного расчёта безопасно создать новый process run с проверенными входами. Не «чинить» state по имени каталога и не удалять потенциально единственную копию. Автоматический distributed recovery/Drive reconciliation не заявляется.
