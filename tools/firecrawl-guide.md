# Firecrawl как заменяемый провайдер

Адаптация upstream tools/firecrawl-guide.md. Триггер — нужна разрешённая операция map/scrape/crawl/search/extract и нет пригодного готового источника. Инструкция не означает подключение, бесплатность или разрешение расходовать credits.

Входы: точные domains/URLs, цель и требуемые поля, лимиты/robots, действующие полномочия и проверенная capability. Перед установкой/подключением сверить текущую первичную документацию провайдера и правила среды; не переносить тарифы из vendor.

Порядок: проверить существующий отчёт/registry → probe конкретного метода → при необходимости ограниченный map → выбрать шаблоны/страницы → разрешённая операция → сохранить raw/provider request ID/time/params/completeness → нормализовать нужный dataset → QA. Map не является полным crawl; scrape не даёт сам по себе трафик, позиции, inbound link database или CWV.

Выход: неизменяемый источник с provenance и coverage, затем work-product предметной роли. Ошибки 401/403 не обходить; 429/5xx обрабатывать лишь в допустимых ограниченных retry; неопределённый платный запуск сначала сверять по фактическому ID. Не отправлять клиентские данные новому получателю без разрешения.

В текущем CLI Firecrawl adapter отсутствует. Codex может использовать реально доступный разрешённый session tool, но в этой разработке paid calls не выполняются. Альтернатива — пригодная готовая выгрузка или разрешённое ограниченное чтение другим источником.
